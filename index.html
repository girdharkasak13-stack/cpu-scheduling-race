Six ways to share one CPU

Each diagram runs the same tiny workload (arrivals staggered on purpose), so you can see how the order — and, for the preemptive algorithms, the interruptions — change.

FCFS

First Come, First Served

Processes are executed in the order in which they arrive.

Type
Selects by
Arrival time (first in, first served)
Advantages, limitations & best use

Advantages

  • Simple to implement and to reason about
  • No starvation: every process eventually runs

Limitations

  • The "convoy effect": one long job delays every job behind it
  • Average waiting time is often far from optimal

Best for: batch systems with no interactivity requirement, or as a fair baseline to compare other algorithms against.

SJF

Shortest Job First

Among available processes, the one with the shortest burst time is selected.

Type
Selects by
Shortest burst time among ready processes
Advantages, limitations & best use

Advantages

  • Provably minimizes average waiting time among non-preemptive algorithms

Limitations

  • Can starve long processes if short ones keep arriving
  • Needs the burst time in advance, which real systems must estimate

Best for: batch workloads where burst times are known or predictable ahead of time.

SRTF

Shortest Remaining Time First

The preemptive version of SJF: whenever a new process arrives with less remaining work than the one running, it takes over.

Type
Selects by
Shortest remaining burst time, re-checked on every arrival
Advantages, limitations & best use

Advantages

  • Optimal average waiting time among all scheduling algorithms for a given arrival pattern
  • Reacts immediately to newly arrived short jobs

Limitations

  • Can starve long processes under heavy load
  • Frequent preemption adds real-world context-switch overhead

Best for: workloads with mixed job lengths where minimizing average waiting time matters more than fairness.

Priority

Priority Scheduling

Among available processes, the one with the best (lowest-numbered) priority is selected.

Type
Selects by
Lowest priority number among ready processes (1 = highest priority)
Advantages, limitations & best use

Advantages

  • Lets important work (e.g. system tasks) go first, by design

Limitations

  • Low-priority processes can starve indefinitely without aging
  • Priority still has to be assigned by someone, correctly

Best for: systems where some processes are genuinely more important than others, such as real-time or system-critical tasks.

Priority (P)

Priority Scheduling, Preemptive

The preemptive version of Priority: a running process is interrupted the moment a higher-priority one arrives.

Type
Selects by
Lowest priority number, re-checked on every arrival (1 = highest priority)
Advantages, limitations & best use

Advantages

  • High-priority work gets the CPU almost immediately, even mid-execution

Limitations

  • Even more prone to starving low-priority processes than the non-preemptive version
  • More context switches than non-preemptive priority scheduling

Best for: soft real-time systems where urgent work must interrupt less-urgent work immediately.

Round Robin

Fair Time Sharing

Each process receives a fixed time quantum before the scheduler moves to another process.

Type
Selects by
Turn order in the ready queue, capped at one time quantum per turn
Advantages, limitations & best use

Advantages

  • No starvation: every ready process gets a turn on a predictable cycle
  • Good response time for interactive workloads

Limitations

  • A quantum that's too small causes excessive context switching
  • A quantum that's too large makes it behave like FCFS

Best for: time-sharing and interactive systems where fairness and response time matter more than average turnaround.

Performance comparison

Each tile compares every selected algorithm on one metric for your current workload. Lowest or highest is not the same as best or worst: it depends on what you care about.

Detailed metrics

Every number comes from the Gantt charts above.

How these numbers are calculated
  • Turnaround time = completion time − arrival time.
  • Waiting time = turnaround time − burst time.
  • Response time = first start time − arrival time (the first time the process ever gets the CPU, even under a preemptive algorithm).
  • CPU utilization = busy time ÷ (last completion − first arrival). Idle gaps between arrivals count as idle.
  • Context switch = the CPU moving from one process to a different one. The first dispatch is not counted, idle gaps are ignored, and switching costs no time in this simulator.
  • Priority convention: a lower priority number means a higher priority. Priority 1 always runs before priority 2 when both are ready.
  • Ties in the non-preemptive algorithms (FCFS, SJF, Priority) go to the earlier arrival, then to the process added first. The preemptive algorithms (SRTF, Priority (P), Round Robin) use the same tie-break when choosing who runs next. In Round Robin, a process that arrives exactly when a quantum ends joins the queue before the preempted process.
